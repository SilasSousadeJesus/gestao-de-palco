# Conhecimento do projeto

Coloque aqui guias curtos para temas que voltam a aparecer e que nao podem ser deduzidos somente pelo codigo. Exemplos: `database.md`, `security.md`, `frontend.md`, `release.md` e `integrations.md`.

## Guias existentes

| Guia | Quando ler |
| --- | --- |
| [`design-system.md`](design-system.md) | Antes de criar ou alterar qualquer botao, input, card, tabela ou icone no console de gestao ou nas telas de palco/preview. |

Cada guia deve responder, de forma objetiva:

1. Quando ele precisa ser lido.
2. Quais invariantes ou regras nao podem ser quebradas.
3. Que arquivos, modulos e comandos sao relevantes.
4. Quais armadilhas ja conhecidas devem ser evitadas.

Evite transformar esta pasta em uma copia da documentacao inteira. Se o agente nao precisa da informacao para tomar uma decisao recorrente, ela provavelmente nao pertence aqui.
